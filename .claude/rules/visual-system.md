# 비주얼 시스템·페이지 구성 (승인됨)

## 색·글꼴·모션
- **배경 (A. Midnight Signal)**: `#02040A`(배경), `#0B1426`(그라데이션) — 계획 6-3에서 첫 화면 하늘과 맞춰 어둡게(전에는 `#070B16`·`#13203A`), `#8FB8FF`(데이터 점), `#EEF3FF`(텍스트)
- **포인트 색**: 호박색 `#FFB547`(공휴일 봉우리, 플립 글자판, 강조 수치)
- **글꼴**: 제목 Space Grotesk Bold 대문자(자간 -0.03em), 본문 Pretendard, 수치·글자판 IBM Plex Mono
- **모션**
  - 플립 글자판: 글자당 약 40ms, 전체 0.8초 이내(예외: ② 플립 보드 약 1.8초·펴질 때 튕김 — 사용자 승인)
  - 텍스트 리빌: 단어 단위로 아래에서 떠오름, 0.9초, 단어당 60ms 지연
  - 이징은 `cubic-bezier(.16,1,.3,1)`(expo.out) 하나로 통일, bounce 금지
- **데스크톱으로 보는 것을 우선** — 화질은 데스크톱 기준, 휴대폰은 가볍게 동작
- `prefers-reduced-motion`·저사양 모바일에서는 3D 대신 정적 이미지, 콘텐츠는 모두 읽을 수 있게

## 점 컨셉 (교수님 피드백 뒤 결정, 2026-10-01~04)
- **점 컨셉은 포기하지 않는다**(모든 그림이 같은 점이 옮겨 가며 만들어진다). 차트 흐름(자막 칸에 맞춰 단계가 넘어감)도 유지
- **점 위계**: 결론 층(평균선·U자·기준선·구간 띠)은 크게·불투명·점 간격 ≤ 지름, 배경 층(관측 표본)은 작게·흐리게. 상수는 `src/charts/*.ts`, 3D는 같은 배치를 쓴다
- **별자리 선**: 가운데 핵심 점만 흰 가는 선(~1px·반투명)으로 잇는다. 바깥(구간·관측 표본)은 선 없이 점 구름만. 굵은 실선·면 덧그림은 쓰지 않는다
- **배경 표본 밀도(2026-10-07)**: U자 표본 16,000·점 1.5, 모델 관측 출발일당 48·1.55, 구름 출발일당 60, 걸러내기·검증 설계 8,000·1.9 — 표본을 늘리면 점을 작게 해 칸·띠 모양이 남게. 3D 점 수는 세로 화면 점 구름(15,926) 아래(`tests/unit/charts-density.test.ts`)

## 페이지 구성 (한 페이지 스크롤, `src/lib/sections.ts` 한 곳에서 순서·번호·옆 목차)
0. 로딩: `NOW BOARDING` → 행 수 플립 카운터 → 호박색 진행선 → `ROWS`(계획 6-2)
- 첫 화면: 밤의 공항 — 스크롤하면 카메라가 활주로로 내려앉고, 점 비행기가 이륙하며 불빛이 지형 점으로(계획 6-5·6-6). `SIGNAL` 큰 제목, 키워드, 오른쪽 아래 공항 좌표·노선 메타 줄, 가운데 아래 `SCROLL`. 스크롤을 빨리 해도 연출은 초당 0.28 진행 이하로 따라온다(옆 목차·`#` 이동은 즉시)
- 머리말(계획 6-5·9-3, 번호 없음): 큰 글 두 줄 + 잡음 밭. 3D가 맨 위에서 켜졌으면(`html.hero-runway`) 230svh로 길어져 **잡음 → 신호**(예약 곡선 8구간 점 → 점 선 → U자 완성·잡음 가라앉음). U자 값은 `terrain.json` `curve`(`bookingBins`). 시계 1 → 1.8, `src/three/signal.ts`, html `data-signal`
1. `01 — PROJECT`: 큰 질문 + 설명 + 숫자 4개. 배경 = U자 + 잡음 흐리게(장면 `about` dim 0.6)
2. `02 — DATA COLLECTION`: (1) 수집 라인 4단계 + 한·일 지도 → (2) 판 없는 공항 플립 보드(모은 행 258,829, facts `data.rawByRoute`·`rawRows`) + 흐린 지도 → (3) 걸러내기 판(`chartFilter`, 자막 칸마다 규칙 적용, 258,829 → 242,874 플립)
3. `03 — MODEL & FEATURES`: 모델 구조 판(`chartModel`, 계획 7-2) → 피처 33개·6그룹 점 와플 → 누르면 SHAP 벌떼(계획 5-3c, Esc로 닫기)
4. `04 — FINDINGS`: 출발일 점 그래프 + 요일 평균 · 구간별 분포 벌떼(U자). 순서 유지(출발일 → U자) + 결론형 제목
5. `05 — VALIDATION`: R² 거품 · 검증 설계 판(`chartSplit`, K-Fold → GroupKFold → TSS, TSS는 폴드가 1.2초마다 저절로, 마지막에서 2.4초 머문 뒤 반복 — 가려진 탭·움직임 줄이기에서는 멈춤) + 평가 방식 표 · 예측 불확실성 구름 · 한계
- 데모(계획 9-2, 시안 B "미니멀 가운데"): 가운데 정렬 한 축, 결과 카드 테두리·바탕 없음, **배경 없음**(`demo` 장면 dim 0)
- 연락처: 가운데 정렬, 가로 탑승권 + 절취선 꼬리표(시안 A, 꾸밈 값 `facts.contact.ticket`), 소개는 560px 가운데 칸·글은 왼쪽 정렬. 좁은 화면은 꼬리표가 아래로. 페이지는 연락처로 끝나고 소개 섹션은 따로 없다 — 소개는 연락처 안에 짧게(신원 한 줄 + 핵심 역량, 2026-10-07 결정)
- 상단 바: 언어 전환 + 이력서 다운로드 — 판 없는 작은 글자 줄, 맨 위·위로 올릴 때 보이고 내리면 숨음. 30초 요약·휴대폰 메뉴 버튼 없음
- 연락처·데모는 사용자가 나중에 다시 만든다 — 그 전까지 공들이지 않는다

## 데모 화면 (B1)
- 문장형 선택 "〔노선〕 가는 〔LCC/FSC〕를 〔출발일〕에 타려면, 지금 살까요?" + **출발일 막대**(D+3~90, 높이 = 기준일 예측가, 공휴일 주변 호박색)가 날짜 선택기. 누르기·끌기·←/→(Home/End)
- 결과: 플립 가격 → q10~q90 띠 → 추천 배지 + 이유, 확신도는 WAIT/DROP일 때만. "미리 계산된 예측 · 2026-09-22 기준" 항상 표기. 초기 선택은 DROP_EXPECTED 조합(`facts.json`)
- `ForecastSource` 인터페이스(`getStrip`, `getForecast`, `meta`) — 지금은 `StaticForecastSource`(`demo.json`), 나중에 `ApiForecastSource`. 실패 → 안내 + 다시 시도, 예측 없는 날짜 → 회색 점선·선택 불가
