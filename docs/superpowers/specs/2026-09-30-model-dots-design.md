# ③ 모델 구조 점 연출 설계 (2026-09-30, 계획 7-2)

> 이야기 흐름 설계(`2026-09-29-story-flow-design.md`) §3.1의 ③ 모델 카드와, CLAUDE.md "점 연출 아이디어" 2번
> (모델 구조 — 점이 추세선 + 잔차로 갈라짐)을 구체화한다. 바뀌는 곳은 ③의 모델 카드("모델 구조")뿐이다.
> 사용자 승인 2026-09-30.

## 0. 목표

- 모델 카드의 글("NeuralProphet 기준 가격 + XGBoost가 벗어난 몫")을 **실제 데이터 점**으로 한 번 더 보여 준다.
  글 세 칸이 차례로 바뀔 때 점이 세 단계로 움직인다: 모은 가격 → 기준 가격 선 → 기준에서 벗어난 몫.
- ML 엔지니어 포트폴리오에서 "하이브리드 모델을 왜 이렇게 나눴는가"를 그림 하나로 읽히게 하는 것이 목적이다. 문구는 담백하게.

## 1. 사용자 결정 (2026-09-30)

| # | 정한 것 |
|---|---|
| 1 | 모델 카드(글 카드 `.chapter`)를 **그림 판 블록**(`.chart-block` + `ChartStage` + 자막 띠 `.chart-copy`)으로 바꾼다. 다른 차트 블록과 같은 방식(판 고정, 문단이 한 칸씩 바뀜) |

| 4 | 3단계는 **시안 A**: 선이 평평해져 점선 0 줄이 되고, 점은 각자의 잔차 높이로 옮겨 간다. 큰 잔차는 호박색 |

| 6 | 네 번째 칸은 지금 `body2`(Optuna·분위수 구간·SHAP) 그대로, 점은 3단계에 머문다 |

## 2. 데이터 — `charts.json`의 `model`

- 추출: `scripts/export_charts.py`. 정상 행(`split_rows`) + 노선·등급 평균 대비 %(`export_terrain.add_route_class_pct`, 지형·차트 1과 같은 정의).
- 관측 표본: 인천→나리타 LCC 행을 고정 시드로 섞은 뒤 **출발일마다 앞에서 12개**(행이 적은 날은 있는 만큼). 출발일 순.
- 기준 가격: 서비스 모델(`v2_predictor.pkl`)의 NeuralProphet 기준을 `V2Predictor.predict_optimal_timing`과 똑같이 만든다 —
  `np_baseline_for_route(np_models, np_dailies, "ICN_NRT", 출발일)` × `class_level_ratio[("ICN_NRT", "LCC")]`, 값이 없거나 0 이하면
  그 노선 기준의 중앙값. 이것을 같은 노선·등급 평균 대비 %로 바꾼다(재학습 없음).
- 형식(정수 = %×10, 원 단위 값은 없다 — 데이터 공개 원칙):
  ```json
  "model": {
    "route": "ICN_NRT", "cabin": "LCC",
    "base": [/* charts.dates와 같은 길이, 출발일별 기준 가격 %×10, 관측 없는 날은 null */],
    "obs": { "date": [/* charts.dates 번호 */], "pct": [/* 관측 %×10 */] }
  }
  ```
- 잔차(3단계)는 사이트가 계산한다: `r = ((1 + obs/100) / (1 + base/100) − 1) × 100` %. 두 값이 같은 평균에 대한 %라
  `obs / base − 1`과 같다. 모델 목표(`log1p(y) − log1p(base)`)와의 차이는 가격이 수만 원대라 0.001% 수준이다.
- 공휴일 호박색(1단계)은 `charts.depart.holiday`(출발일 ±3일 공휴일 코드, 차트 1과 같은 것)를 그대로 쓴다.
- 다른 키(`dates`·`depart`·`labels`·`curve`·`shap`)는 한 글자도 바뀌지 않아야 한다(재생성 뒤 비교).

## 3. 화면

- 판: 다른 차트와 같은 `.chart-plot`(데스크톱 11vh~57vh, 휴대폰 9vh~51vh). 가로 = 출발일(실제 날짜 간격), 세로 = %(−60~+110, 밖은 가장자리로 자름).
  눈금 +100·+50·0·−50 %, 아래 월 이름(차트 1과 같은 규칙), 왼쪽 위 축 이름.
- 1단계 **모은 가격**: 관측 점(출발일마다 12개, 좌우로 조금 흔듦). 공휴일 무렵 출발일은 호박색. 축 이름 "노선·등급 평균 대비".
- 2단계 **기준 가격**: 관측 점은 흐려지고(알파 0.2), 같은 %눈금에 밝은 점선(점 240개)이 기준 가격을 따라 그려진다. 선 오른쪽 끝에 "기준 가격" 이름표.
- 3단계 **벗어난 몫**: 선이 0 높이로 평평해지며 끊긴 점선이 되고, 관측 점은 각자의 잔차 높이로 옮겨 간다. |잔차| ≥ 50%(`MODEL.residHot`)는 호박색. 축 이름 "기준 가격 대비".
- 점 순서·개수·`group`은 세 단계가 같다 → 3D에서는 같은 지형 점이 단계 사이를 옮겨 다닌다(배치 `variant: 'stage:<n>'`가 바뀌면 반대 슬롯, 계획 5-3c `pickSlot`).
  `group` = 지형 출발일 번호(관측 점·선 점 모두) — 그 출발일의 지형 점이 모인다(차트 1과 같다).
- 3D가 꺼지면 같은 배치를 2D로 그린다(ChartStage 기존 동작). 조작 층·표시 상자 없음.

## 4. 단계 전환

- 자막 스크립트(`motion/caption.ts`)가 지금 문단 번호를 블록에 `data-para`로 적는다(이미 `.is-on`을 붙이는 같은 자리).
- `ChartStage`에 `stages`(단계 수)를 주면 블록의 `data-para`를 지켜보다 `단계 = min(문단, stages − 1)`이 바뀌면 다시 배치하고,
  판(`.chart-stage`)에 `data-stage`를 적는다(e2e·디버깅용).

## 5. 장면 키

- `model`(지형 장면) → **`chartModel`**(차트 장면, 정면 차트 카메라). `ChartKey`와 `SceneKey`에 같은 이름. 차트 1·2·4의 `chart*` 이름과 맞췄다.
  세로 화면 전용 `model` 카메라 값은 지운다(차트 장면은 세로 화면에서도 카메라가 같다).

## 6. 문구 (`features.structure.*`, 세 언어 같은 키)

- `heading` 그대로(h2 `#features-h`, 제목 리빌 대상). 섹션 머리표 `03 — MODEL & FEATURES`와 h2는 블록 위 `.charts-head`로 옮긴다(④·⑤와 같은 모양).
- `step1`(새): "출발일마다 모은 인천→나리타 LCC 가격입니다. 같은 날 떠나는 편도 언제 샀느냐에 따라 흩어집니다."
- `step2`: 지금 `body1` 첫 문장(NeuralProphet 기준 가격). `step3`: `body1` 둘째 문장(XGBoost, {model.featureCount}) + `flow` 줄. `body1`은 지운다.
- `body2` 그대로(넷째 칸). 코드 보기 링크 그대로.
- `axis`("노선·등급 평균 대비"), `axisResid`("기준 가격 대비"), `line`("기준 가격") — 판 이름표. `alt` — 화면 낭독기용 한 문단(`.sr-only`).
- en·ja는 Claude 초안 → 사용자·검수자 검토(늘 하던 순서).

## 7. 테스트

- pytest: 표본 모양(출발일마다 ≤12, 날짜 번호 ⊂ charts.dates), 시드가 같으면 같은 표본, 기준 % 정의·null, 블록 키에 원 단위 값 없음.
- 단위: 배치(단계별 점 개수 같음, 0..1 안, 3단계 선은 한 높이(0), 1단계 공휴일 호박색, 3단계 큰 잔차 호박색, `variant`), 스키마(`model` 길이 검사), 장면 표(`chartModel`은 차트 장면).
- e2e(3D 꺼짐): 스크롤로 문단이 바뀌면 `data-stage`가 0→1→2, 2D가 그려짐, axe 위반 없음, 휴대폰 가로 스크롤 없음. 옛 모델 카드 화소 대비 검사(`[data-scene="model"]`)는 지운다 — 자막 띠에는 점이 오지 않는다.
