## 0. 목표

- 와플은 "어떤 피처 그룹이 모델에서 얼마나 쓰였나(gain %)"만 보여 준다. 펼치면 **그 그룹의 피처가 실제 예측에서 가격을 어느 쪽으로 얼마나 움직였는지**(SHAP)를 점으로 보여 준다.
- ML 엔지니어 포트폴리오에서 "모델을 해석할 줄 안다"를 한 번의 누르기로 보여 주는 것이 목적이다. 설명 문구는 담백하게, 사실만.

## 2. 데이터 — `charts.json`의 `shap`

- 추출: `scripts/export_charts.py`에 SHAP 단계를 더한다. 항공권 저장소 `src/models/shap_analysis.py`처럼 `v2_predictor.pkl`을 불러와 트리 부분 `booster.predict(DMatrix, pred_contribs=True)`로 계산한다(재학습 없음, 로드 약 17초). 모델 입력은 피처 33개 그대로(범주형도 한 열)라 열 = 피처.
- 표본: 필터를 통과한 행(242,874)에서 **고정 시드로 150개**를 고르게 뽑는다(같은 입력이면 같은 표본). 옛 설계의 "검증 구간에서"는 쓰지 않는다 — SHAP은 서비스 모델이 실제 데이터에서 무엇을 보는지를 보여 주는 것이라 전체 기간에서 고르게 뽑는 편이 대표성이 있다.
- 형식(키 순서 고정, 정수로 줄여 용량 절약):
  ```json
  "shap": {
    "n": 150,
    "features": ["rd_med", "…33개, 모델 입력 순서"],
    "categorical": ["origin", "destination", "route", "airline", "airline_class"],
    "v": [[…150개 정수…], …33줄],   // SHAP(log 잔차) × 1000, 반올림
    "f": [[…150개 0~100 정수…], …33줄] // 그 피처 값의 표본 안 순위 백분위(범주형은 50 고정)
  }
  ```
  - 피처 값 색은 원값이 아니라 **그 피처 안 순위(0~100)**로 저장한다 — 원값을 공개하지 않고(데이터 공개 원칙), 치우친 분포도 색이 고르게 퍼진다.
  - 용량 예상 약 15~20KB(gzip 전). `charts.json` 파일명 버전 규칙 그대로.
- 사이트 표시 단위: `pct = (exp(v/1000) − 1) × 100` (%). 가로축 범위는 그룹마다 |pct|의 98번째 백분위로 좌우 대칭, 밖의 점은 가장자리에 붙이지 않고 버린다(④ 벌떼와 같은 이유 — 겹쳐 밝은 막대가 된다).
- 그룹 ↔ 피처 대응은 `facts.json`의 `model.featureGroups[].features`를 그대로 쓴다. pytest가 `shap.features`의 집합 = 모든 그룹 피처의 합집합(33개)임을 확인한다.

## 3. 화면 (배치 A)

### 3.1 닫힌 상태
지금 와플 그대로(마우스 올리면 피처 이름 설명 줄). 와플 그룹 이름표가 버튼이 된다(§5).

### 3.2 펼친 상태 — 판(`.chart-plot`, 46vh) 안

| 영역 | 내용 |
|---|---|
| 맨 위 줄(데스크톱 약 판 높이 18%) | 작은 와플 6개 한 줄(각 10×10, 켜진 점 수 그대로) + 그룹 이름 한 줄. 고른 그룹 호박색, 나머지 알파 × `FOCUS_DIM` |
| 그 아래 한 줄 | "〔그룹〕 · 〔gain〕% · 〔n〕개 — 점 하나 = 예측 하나에서 이 피처가 가격을 움직인 정도" + 오른쪽 색 범례(값 낮음 → 높음) |
| 나머지 | 벌떼: 피처마다 가로줄 하나, 줄 왼쪽에 피처 이름(HTML, 모노 11px), 가운데 0% 점선. 점 = 표본 하나(그 피처의 pct), 같은 열에서 위아래로 번갈아 비켜 쌓음, 줄 높이 45%를 넘치면 버림 |
| 바닥 | 가로축 `← 가격을 내림 · 0% · 가격을 올림 →` + 좌우 끝 눈금(±x%) |

- **줄 순서**: 그 그룹 안에서 평균 |SHAP|가 큰 피처부터 위로.
- **색**: `f`(0~100)를 파랑(`#5A8CFF` 계열) → 호박(`#FFB547`) 사이로. 범주형 피처는 중간색 한 가지(`TONE.dot`) + 이름 옆 작은 표시 "범주형". 3D 셰이더·2D 그리기 모두 새 색 경로가 필요하다(§4).
- **점 개수**: 그룹 피처 수 × 150(최대 lookup 13 × 150 = 1,950) + 작은 와플 600. 3D 점 구름(약 2.6만)으로 충분.
- **휴대폰(판 폭 < 560px)**: 같은 구조. 작은 와플 줄은 6개 한 줄(칸이 좁아 이름 대신 %만), 피처 이름 9px, 이름 칸 폭을 줄이고 벌떼 점 지름을 줄인다. 13줄이 42vh에 들어가도록 줄 높이를 판 높이에서 계산한다.

### 3.3 전환
- 펼침·닫힘·그룹 바꾸기 때 점은 옛 자리에서 새 자리로 옮겨 간다(3D: 차트 슬롯을 반대 슬롯으로 바꿔 쓰기 — 같은 차트 키라도 펼침 상태가 바뀌면 새 배치로 본다. 이징 expo.out, 튕김 없음). 2D는 바로 다시 그린다.
- reduced-motion·대체 화면: 옮겨 가는 연출 없이 바로 바뀐다. 펼치기 자체는 대체 화면에서도 된다(2D 그리기가 같은 배치를 그린다). 원래 설계의 "대체 화면에서는 목록으로 대신"보다 낫고 추가 비용이 없다.

## 4. 코드 구조

- `src/charts/layouts.ts`: `waffleLayout(groups, size, fmt, open?: number)` — `open`이 없으면 지금 그대로, 있으면 §3.2 배치(작은 와플 줄 + `shapSwarmLayout` 결과를 합친다). 벌떼 배치는 순수 함수 `shapRows(shap, featureIds, size…)`로 따로 두어 단위 테스트한다.
- `src/charts/data.ts`: zod 스키마에 `shap` 추가(33줄 × n 길이 검사).
- 색: 점마다 색 번호(tone) 외에 **값 색(0~1, 없음 = −1)** 을 하나 더 둔다(`ChartLayout.val: Float32Array`). 3D는 속성 하나(`aVal`) 추가, 셰이더 `toneColor`에서 `val ≥ 0`이면 파랑↔호박 보간. 2D `draw2d.ts`도 같은 규칙.
- `ChartStage.tsx`: 와플 전용 상태 `open`(−1 = 닫힘). `open`이 바뀌면 `buildLayout`을 다시 불러 `publishChart`. 3D 쪽(`TerrainScene`·`chartTargets.pickSlot`)은 같은 키라도 배치 객체가 바뀌고 **펼침 상태가 바뀌면** 반대 슬롯에 쓴다(지금은 같은 키 = 같은 슬롯이라 점이 튄다). 창 크기 변경은 지금처럼 같은 슬롯.
- 이름표: 새 `ChartLabel` 종류 `feature`(줄 왼쪽 피처 이름·범주형 표시), `legend`(색 범례), 기존 `text`(축·눈금)·`group`(작은 와플에서는 compact 한 줄).
- 강조(`hl`)는 그대로 그룹 번호. 펼친 동안 강조 = 펼친 그룹(마우스 올리기로 바뀌지 않음).

## 5. 조작과 접근성

- 와플 그룹 이름표(`.chart-group`)를 `aria-hidden` 층에서 꺼내 **`button`** 으로: `aria-expanded`, `aria-controls`(펼침 목록), 이름 = "〔그룹〕 〔gain〕% · 〔n〕개 피처". 캔버스·점은 계속 `aria-hidden`.
  - 이름표 층 전체의 `aria-hidden`을 풀지 않고, 버튼들만 따로 접근 가능한 층(`.chart-groups`)에 둔다 — 축·눈금 글자가 낭독되지 않게.
- 누르기(마우스·손가락)·Enter/Space: 닫혀 있으면 그 그룹 펼침, 같은 그룹이면 닫힘, 다른 그룹이면 바꿈. 한 번에 하나.
- Esc: 판 안에 초점이 있거나 펼친 상태면 닫고 초점을 그 그룹 버튼으로 돌려놓는다.
- 마우스 올리기 강조(설명 줄)는 닫힌 상태에서만 지금처럼. 손가락은 지금 "누르면 강조 토글"이던 것을 "누르면 펼침"으로 바꾼다(설명 줄 내용은 펼친 화면 위 줄이 대신한다).
- 화면 낭독기: 펼치면 `.chart-copy` 안 숨은 목록(`#waffle-shap`, `sr-only`)에 그 그룹 피처마다 한 줄 — "〔피처〕: 평균 영향 ±x%, 값이 높을수록 가격을 올림/내림"(범주형은 방향 대신 "범주형"). 방향은 피처 값 순위와 SHAP의 상관 부호로 정한다(|상관| < 0.2면 "방향 일정하지 않음"). 펼치거나 바꿀 때 한 번 `role=status`로 "〔그룹〕 펼침" 알림.
- 포커스 링은 기존 호박색 규칙.

## 6. 문구 (3개 언어, `content/*.json` — 숫자 직접 기입 금지)

- `features.shap.lead`: 점 하나 = 예측 하나에서 이 피처가 가격을 움직인 정도
- `features.shap.down` / `up`: 가격을 내림 / 가격을 올림
- `features.shap.low` / `high`: 값 낮음 / 높음
- `features.shap.categorical`: 범주형
- `features.shap.rowUp` / `rowDown` / `rowMixed` / `rowCat`: 숨은 목록 문장 틀(`{name}`·`{pct}`)
- `features.shap.open` / `close`: 버튼 상태 알림("{group} 펼침" / "닫힘")
- `features.hint`(지금 "마우스를 올리면…")에 "누르면 펼침"을 더한다.
- 한국어 초안 → 사용자 검토, 영·일 초안(기존 규칙).

## 7. 테스트

- pytest(`scripts/tests`): `shap.features` 33개 = 모델 입력 열 = facts 그룹 피처 합집합, `v`·`f` 모양 33 × n, `f` 범위 0~100, 범주형 `f` = 50, 시드 고정(두 번 뽑아도 같음).
- 단위: `shapRows` — 줄 수 = 그룹 피처 수, 줄 순서 = 평균 |SHAP| 내림차순, 한 줄 안 점 겹침 없음, 범위 밖 점 버림, 범주형 `val = −1`·비범주형 0~1; `waffleLayout(open)` — 작은 와플 켜진 점 수 = 반올림 gain, 모든 점·이름표가 판 안(0~1); 데이터 스키마; 새 문구 키 3개 언어 일치·숫자 없음(기존 테스트가 잡음).
- 3D 단위: 펼침 상태가 바뀌면 `pickSlot`이 반대 슬롯, 창 크기 변경은 같은 슬롯.
- e2e(desktop·mobile): 와플 버튼 누르기 → 피처 이름표 n개 보임·`aria-expanded=true`; Enter로 열기, Esc로 닫기(초점 복귀); 작은 와플 누르면 다른 그룹으로 바뀜; 펼친 상태 axe 통과; 휴대폰 폭 가로 스크롤 없음; 펼친 상태 이름표가 판 밖으로 안 나감; 3D 꺼짐(reduced-motion)에서도 펼침 동작.
- 용량: 초기 JS 한도(150KB) — 새 코드는 배치 청크(`import()`)에 들어가므로 초기 JS는 버튼·상태 몇 줄만 는다. `npm run size`로 확인.

## 8. 범위 밖

- 점 하나 짚어 값 보기(표시 상자) — 넣지 않는다.
- 피처 이름 번역(피처 이름은 코드 이름 그대로 — 모델 열 이름이 곧 사실).
- SHAP 상호작용·의존도 그림.
