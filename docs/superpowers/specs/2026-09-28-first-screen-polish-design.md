## 1. 배경 B — 본문을 하늘만큼 어둡게

원인: 첫 화면 하늘(`.backdrop::before`)은 `#010206`~`#02040a`로 거의 검정인데, 본문 바탕은 `#070B16` + 위쪽 `#13203A` 남색 빛이다. 첫 화면을 벗어나면 하늘이 0.8초에 걸쳐 사라지며 남색이 드러난다.

- 색 토큰(`src/styles/globals.css :root`): `--bg: #070B16 → #02040A`, `--bg2: #13203A → #0B1426`
  - `--bg`는 하늘의 땅 색(`#02040a`)과 같다. 그래서 하늘이 사라져도 아래쪽 색은 바뀌지 않고, 위쪽의 옅은 남색 빛만 살짝 드러난다
- 같은 색을 숫자로 박아 둔 곳도 모두 맞춘다
  - 비네트 `rgba(7, 11, 22, …)` → `rgba(2, 4, 10, …)`(`.backdrop::after`, `.hero .scene-figure::after`, 휴대폰 아래쪽 비네트)
  - 글자 그림자 `#070B16`(`.data-board`)
  - 대체 이미지 캡처의 바탕 채우기(`scripts/capture-fallbacks.mjs`의 `flatten`)
  - 파비콘 `app/icon.svg` 바탕
  - 그 밖에 `rgba(7, 11, 22, …)`로 쓴 반투명 판(언어 안내 등)
- **떠 있는 판**(탑승권 `.pass`, 데모 결과 `.demo-result` 등 `rgba(19, 32, 58, .5)`)과 플립 글자판 색은 **그대로 둔다**. 바탕이 어두워지면 오히려 더 또렷이 구분된다
- 대비: 글자·바탕 대비는 좋아지기만 한다. 기존 대비 검사(`terrain.spec` 4.5:1 화소 검사, axe)가 그대로 지킨다
- 확정된 비주얼 시스템(CLAUDE.md "A. Midnight Signal")의 배경색 두 개를 이 값으로 고친다

## 2. 점 D — 겹쳐도 안 타게, 멀수록 흐리게

원인: 점 재질이 빛 더하기(`THREE.AdditiveBlending`)라 점이 겹치는 곳이 하얗게 탄다. 신호 점 알파도 0.95로 높다.

### 2.1 그리기 방식

- **지형·지도·차트 점은 보통 섞기**(겹쳐도 더 밝아지지 않음), **공항 불빛만 빛 더하기**를 유지한다(불빛 번짐이 공항 장면의 핵심이라).
- 재질은 하나(`Points` 하나, 기존 구조 유지)이므로 섞는 방식을 점마다 정한다: 미리 곱한 알파(premultiplied) 섞기 — `src = ONE, dst = ONE_MINUS_SRC_ALPHA`로 두고, 조각 셰이더가 `vec4(color * a, a * (1.0 - vAir))`를 낸다. `vAir = 0`(지형)이면 보통 섞기, `vAir = 1`(공항 불빛)이면 빛 더하기와 같다. 공항 → 지형으로 넘어가는 동안 `vAir`가 줄며 자연스럽게 바뀌어, 재질의 섞기 방식을 도중에 바꿀 때 생기는 튐이 없다.
- 캔버스는 투명(`alpha: true`)이라 페이지 바탕과 합성된다. three의 기본(premultipliedAlpha) 합성과 맞는지 구현 때 캡처로 확인한다.

### 2.2 밝기·크기 (시안 D의 값)

| | 지금 | D |
|---|---|---|
| 신호 점 알파 | 0.95 | **0.8** |
| 잡음 점 알파 | 0.18 × 장면 `noise` | **0.117 × 장면 `noise`** (① 장면 noise 0.6에서 약 0.07) |
| 신호 점 크기 | 1.0 | **0.9** |
| 잡음 점 크기 | 0.7 | **0.6** |
| 제거 레이어(차트 3) | 0.9 | 그대로 |

- **거리 흐림**: 지형·지도 점(차트 점·공항 불빛 제외)의 알파에 곱한다.
  `fade = clamp(0.79 − (d − dT) / 18, 0.22, 1)` — `d`는 카메라에서 점까지 거리(`−mv.z`), `dT`는 카메라에서 장면 목표점까지 거리(새 유니폼 `uFocusDist`, `CameraRig`가 매 프레임 넣는다). 목표점 거리 기준이라 멀리 물러난 장면(검증·데모·연락처)에서도 가까운 쪽 절반은 밝게 남는다. 상수는 ① 장면(`about`, dT ≈ 22.2)에서 시안 D와 같아지도록 맞춘 값이다. 구현 때 장면마다 캡처해 확인하고, 필요하면 상수만 조정한다
- 차트 점: 거리 흐림 없음. 섞기 방식이 보통 섞기가 되어 **2D 대체 그림(`draw2d.ts`, `source-over`)과 오히려 더 같아진다**
- 공항 불빛: 밝기·번짐 그대로

## 3. 상단 바 E

- **모양**(공항 시안 `.top`과 같은 결): 판·아래 선·둥근 버튼을 없앤다. 글자는 IBM Plex Mono 500, 11px, 자간 0.22em, `--mute` 색. 왼쪽 `SIGNAL`(글자색 `--tx`), 오른쪽 `KO · EN · JA` + `이력서`(없으면 `이력서 준비 중`, 흐리게). 지금 언어는 `--tx`, 나머지는 흐리게. 좌우 끝은 본문 `.wrap`(최대 1080px) 줄에 맞춘다 — 왼쪽 끝이 이름 `CHOI HALIM`과 같은 선
- **자리**: 흐름 안의 `sticky` 대신 화면 위에 겹쳐 뜨는 `fixed`로 바꾼다. 처음부터 그렇게 그려지므로 57px이 빠져도 CLS는 없다
- **동작**
  - 맨 위(스크롤 80px 미만): 전부 보인다
  - 아래로 내리는 중: 전부 사라진다(투명도 + 살짝 위로, 0.4초, `expo.out`)
  - 위로 올리면(누적 8px 이상): **오른쪽(언어·이력서)만** 다시 나타난다. `SIGNAL`은 맨 위에서만
  - 숨은 동안에는 누를 수 없다(`pointer-events: none`, `visibility`로 초점도 막음)
  - **키보드**: 상단 바 안 링크에 Tab 초점이 오면 항상 나타난다(`:focus-within`). 건너뛰기 링크는 지금대로
  - 움직임 줄이기: 전환 없이 바로 보이고 숨는다
  - 스크롤 방향 판정은 한 곳(작은 클라이언트 컴포넌트)에서 하고, `html`의 속성(예: `data-header="top|hidden|peek"`)만 바꾼다. 모양은 CSS가 맡는다. 초기 JS 예산(150KB)에 영향이 거의 없는 크기로
- **결정 변경**: "항상 보이는 이력서 다운로드 버튼"(CLAUDE.md 페이지 구성) → **"맨 위와, 위로 올릴 때 나타나는 이력서 버튼"**. 사용자가 E를 고르며 받아들였다(2026-09-28). 연락처 섹션의 이력서 버튼은 그대로라 끝까지 읽은 사람은 늘 받을 수 있다
- 휴대폰: 같은 동작. 375px에서 한 줄(기존 e2e 기준 72px 미만) 유지
- `scroll-padding-top: 72px`은 상단 바가 더는 자리를 차지하지 않으므로 24px로 줄인다(옆 목차로 이동할 때 제목이 너무 아래 오지 않게)

## 4. 스크롤 표시

- 첫 화면 가운데 아래(화면 아래에서 4.5vh)에 `SCROLL`(IBM Plex Mono 500, 10px, 자간 0.3em, 흐린 글자색) + 그 아래 가는 세로선(1px × 34px, 위에서 아래로 떨어지는 2.4초 반복, `expo.out`). 시안 `01-night-airport.html`의 `.scroll` 그대로
- 조금이라도 내리면(스크롤 40px 이상) 사라지고, 맨 위로 돌아오면 다시 보인다. 상단 바와 같은 스크롤 판정 컴포넌트가 `html` 속성으로 알린다
- 장식이라 `aria-hidden`. 움직임 줄이기에서는 선이 멈춰 있다(길이 그대로)
- 3D 꺼짐에서도 보인다(첫 화면 구성은 같다). 오른쪽 아래 메타 줄(`.hero-meta`)과 겹치지 않는다(가운데 vs 오른쪽)
- 로딩 화면이 떠 있는 동안에는 숨는다(로딩이 사라진 뒤 나타남)

## 6. 테스트

- 상단 바 e2e(`site.spec`) 고침: 맨 위에서 보임 → 내리면 숨김 → 올리면 오른쪽만 → Tab 초점에 나타남. 휴대폰 폭 한 줄·언어 전환 보임은 맨 위 기준으로 유지. "준비 중" 검사는 그대로
- 스크롤 표시: 맨 위에서 보임, 내리면 사라짐, 움직임 줄이기에서 애니메이션 없음
- 대비: 기존 화소 검사·axe 통과(바탕이 어두워져 여유가 는다)
- 점: 셰이더 단위 테스트는 없다(WebGL 결과는 단위 테스트로 못 잰다). 거리 흐림 식은 순수 함수로 빼 단위 테스트하고(셰이더에는 같은 상수를 문자열로 넣는다 — 와플 `FOCUS_DIM`과 같은 방식), 나머지는 장면별 캡처로 눈 확인(① 지형, ② 지도, ③·④ 차트, 공항 → 지형 전환)
- `npm run fallbacks`로 대체 이미지 다시 캡처(바탕색·점이 바뀌었다). `npm run size` 통과
- **OG 이미지**: 이번 계획 끝에서 `npm run og`로 다시 캡처할지 사용자에게 묻는다(계획 6-2에서 미룬 결정 — 배경·점이 바뀐 뒤에 정하는 게 맞다)
