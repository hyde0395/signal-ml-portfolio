# 배경 표본 밀도 + TSS 반복 (설계)

- 날짜: 2026-10-07 (맥북)
- 배경: 사용자 "뭔가 점을 더 촘촘하게 박을 순 없나?" — 점 위계(PR #28)·정보 전달 2(PR #30) 뒤 운영 화면에서 배경 층(관측 표본)이 성기게 보인다. "결론 선을 점으로"가 아니라 **배경 표본을 더 많이**로 정함
- 시안(승인): `docs/superpowers/mockups/2026-10-07/` — `density.html`·`density-entry.ts`(사이트 배치 함수 + 실제 데이터, 표본만 다시 뽑음, `density-gen.py`), 캡처 `density-ucurve.png`·`density-model.png`·`density-tss-loop.png`
- 결정(2026-10-07 사용자): ④ U자는 **U3**(표본 16,000·점 1.5), 나머지 차트는 제안대로(③ 모델 4배, ⑤ 구름·② 걸러내기·⑤ 검증 설계 2배), ⑤ 검증 설계 TSS는 **반복**(1.2초 간격, 마지막 폴드 2.4초 머묾)

## 1. 지킬 것

- 점 위계 규칙(`visual-system` 규칙 "점 위계"): 결론 층(별·별자리 선·기준 가격 선·이름표)·알파·색은 바꾸지 않는다. **배경 층의 점 수와 크기만** 바꾼다
- 같은 배치를 3D와 2D가 그린다 — 상수만 바꾸면 둘 다 바뀐다
- 문구 변경 없음

## 2. 차트별 밀도

| 차트 | 표본 (지금 → 새) | 배경 점 크기 넓은 판 (지금 → 새) | 좁은 판 |
|---|---|---|---|
| ④ 차트 2 U자 벌떼 (`SWARM`) | 4,000 → **16,000** | 2.4 → **1.5**, 간격 0.5 → **0.3** | 같은 상수(판 폭과 무관) |
| ③ 모델 구조 관측 점 (`model.ts`) | 출발일마다 12 → **48** (약 8,300) | 2.2 → **1.55** | 1.7 → **1.2** |
| ⑤ 차트 4 예측 구름 (`CLOUD`) | 출발일마다 30 → **60** | 가운데 50% 층 2.5 → **2.1**, 바깥 2 → **1.7** | 같은 상수 |
| ② 걸러내기 (`filter.ts`) | 4,000 → **8,000** | 2.2 → **1.9** | 1.7 → **1.45** |
| ⑤ 검증 설계 (`split.ts`) | 4,000 → **8,000** | 2.2 → **1.9** | 1.6 → **1.4** |

- U자: 점을 작게 해야 구간 칸 한 줄에 더 많이 들어가 칸이 네모로 꽉 차지 않고 분포 모양(방추형)이 남는다(시안 C에서 확인). 그려지는 점은 칸 폭을 넘는 것을 버려 약 13,000
- 크기 상수는 지금 배치 함수 안에 숫자로 박혀 있다(`model.ts`·`filter.ts`·`split.ts`의 `const dot = wide ? … : …`) — 각 파일의 상수 객체(`MODEL`·`FILTER`·`SPLIT`)로 옮긴다(`dotWide`·`dotNarrow`)
- 바꾸지 않는 차트: ④ 차트 1 출발일(결론 층), ③ 와플·SHAP, 머리말·①, ⑤ 차트 3 아령, 데모, 연락처

## 3. 데이터

- `scripts/export_charts.py`: `SAMPLE_SIZE` 4000 → 16000, `MODEL_PER_DATE` 12 → 48, `FILTER_SAMPLE`·`SPLIT_SAMPLE` 4000 → 8000. `MODEL_PER_DATE` 주석의 "차트 1의 출발일 뭉치와 같은 12개"는 지운다(이제 따로 간다)
- `npm run charts`로 `public/data/charts.2026-09-22.json`을 다시 만든다(손 편집 금지 훅). 서비스 모델 로드 약 17초
- 용량: 시안 데이터로 잰 값 — 지금 gzip 약 40KB, 새 구성 약 90KB 예상(4배 전부일 때 111KB). 예산 `MAX_GZIP_BYTES` 150KB 안이고 스크립트가 넘으면 멈춘다
- 표본 seed는 그대로(7) — 같은 seed라도 표본 수가 바뀌면 뽑힌 행이 달라진다. 수치(facts)는 표본과 무관해 바뀌지 않는다. 다만 `refresh_derived`가 charts에서 계산하는 값(`insight.curveMin` 등)은 표본이 아니라 구간 평균·출발일 %에서 오므로 그대로여야 한다 — 다시 만든 뒤 `data/facts.json` diff가 없는지 확인

## 4. 3D 점 수

- 3D는 차트 점마다 지형 점 구름(밝은·흐린 합 약 26,500개)에서 하나씩 배정한다(`src/three/chartTargets.ts` `assignPoints`). 모자라면 **남은 점을 조용히 버린다**(`break`) — 배치 함수가 별·선 점을 표본 뒤에 더하므로 버려지면 결론 층이 사라진다
- 새 최대: U자 약 13,000 + 별·기준 점선, 모델 약 8,300 + 기준 선 240 + 0 점선. 여유 있음
- **단위 테스트 추가**: 실제 `charts.json`으로 만든 각 차트 배치의 점 수(`layout.n`)가 3D 점 구름 수(`terrain.json`에서 `kind ≤ 1.5`인 점) 이하
- 밝기: 3D 점은 미리 곱한 알파 섞기에서 조각 셰이더가 점마다 보통 섞기/빛 더하기를 고른다(`TerrainPoints.tsx`·`shaders.ts`). 빛 더하기 쪽이면 점이 많아질수록 같은 알파에서도 밝아진다. 구현 뒤 3D 켜짐 캡처로 보고, 너무 밝으면 그 차트의 배경 층 알파만 낮춘다(결론 층 대비가 기준)

## 5. ⑤ 검증 설계 TSS 반복

- 지금: TSS 단계(stage 2)의 sub 0~4가 1.2초마다 올라가 폴드 5에서 멈춘다(`subTimer.ts` `startSubs`)
- 새로: 마지막 sub에서 **2.4초 머문 뒤 0으로** 돌아가 반복
  - `startSubs`에 `loopHoldMs?: number` — 주면 마지막에서 그만큼 기다렸다가 `n = 0`으로 이어 간다. 안 주면 지금처럼 멈춤
  - `ChartStage`에 `subLoopMs?: number` prop → `startSubs`에 넘김. ⑤ 검증 설계 블록만 준다(`SPLIT.loopHoldMs = 2400`). ② 걸러내기(점이 떨어짐)·③ 모델 구조(기준 가격으로 모임)는 한 번 일어나야 뜻이 있어 반복하지 않는다
  - 판이 절반 이상 보일 때만(지금 IntersectionObserver 그대로), 나가면 멈추고 다시 들어오면 폴드 1부터
  - 움직임 줄이기: 지금처럼 마지막 모습만(반복 없음)
- 바뀌는 글자는 `FOLD n / 5`뿐 — 점수판(▶ TSS R² · MAE)은 sub와 무관해 깜빡이지 않는다. 3D는 점 위치가 같고 색·알파만 바뀐다
- 폴드 1로 돌아갈 때 점 전환은 다른 sub 전환과 같은 연출(따로 만들지 않는다)
