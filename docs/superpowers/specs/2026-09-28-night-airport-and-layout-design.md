## 1. 원칙: 글과 그림이 같은 자리를 나눠 쓰지 않는다

사용자 지적(2026-09-28):
- 설명 글 뒤의 반투명 검은 판이 거슬린다. 그렇다고 그냥 없애면 가독성이 떨어질 것 같다.
- 스크롤하면 글이 위로 올라가며 차트·점과 겹쳐 지저분하다.

두 문제는 원인이 같다. 글과 그림이 같은 자리를 쓰기 때문에 판이 필요하고, 스크롤하면 겹친다. 그래서 **자리를 나눈다.** 판(배경 상자)은 쓰지 않는다. 대비가 모자란 곳은 판 대신 **장면 구도**(점이 글 쪽에 오지 않게)와 **테두리 없는 옅은 어둠**(캔버스 가장자리 비네트처럼 경계가 보이지 않는 것)으로 지킨다. WCAG AA 대비 기준은 그대로다.

## 2. 그림 판 블록의 자막 방식 (계획 6-1)

대상: `.chart-block`(③ `features`, ④ `chartDepart`·`chartCurve`·`chartCloud`).

- **화면 나누기**: 그림 판(`.chart-plot`)은 지금처럼 화면 위쪽(데스크톱 11vh~57vh, 휴대폰 9vh~51vh)에 둔다. 글(`.chart-copy`)은 그 **아래 띠에 고정**(sticky)한다. 띠는 그림 판 아래 약 4vh 떨어진 곳에서 시작해 화면 아래쪽 여백까지다. 글과 그림 판은 어떤 스크롤 위치에서도 겹치지 않는다.
- **글은 제자리에서 바뀐다**: 블록이 바뀌면 이전 글은 흐려지며 사라지고 새 글이 같은 자리에 나타난다(기존 이징 `expo.out`, 약 0.5초). 글이 화면을 가로질러 올라가는 움직임은 없다. 블록 안에서 스크롤하는 동안 글은 움직이지 않는다.
- **글 뒤 판 없음**: `.chart-copy`의 `background`, 둘레 둥근 판을 없앤다. 아래 띠에는 점이 오지 않으므로 판이 필요 없다.
- **폭**: 데스크톱은 글 폭을 지금처럼 560px 안쪽으로 두고 왼쪽 정렬한다. 휴대폰은 본문 폭 전체.
- **긴 글**: 문단이 3개인 블록(`chartCloud`)은 띠에 다 들어가지 않을 수 있다. 띠 높이를 넘으면 글 크기를 줄이지 말고 **블록 안에서 문단을 차례로 바꿔 보여 준다**(같은 자막 방식). 화면 낭독기와 3D 꺼짐 상태에서는 모든 문단이 차례로 흐른다(§6).
- **3D 꺼짐(`data-3d="off"`)**: 2D 캔버스 그림도 같은 판 위치에 그려지므로 배치는 같다. 움직임 줄이기에서는 흐려짐 전환 없이 바로 바뀐다.
- **섹션 제목 줄**(`④ charts-head`의 `.text-scrim`)도 판을 없앤다. 제목은 그림 판이 고정되기 전에 지나가므로 점과 겹치지 않는 자리(블록 사이)에 둔다.

### 2.1 다른 섹션의 판도 없앤다

- `html[data-3d="on"] :is(.chapter, #project, #demo, #contact)`의 왼쪽 그라데이션 판, `.text-scrim`의 판(첫 화면 `hero-copy`, ① `project`)을 없앤다.
- 대신 해당 장면의 카메라 구도로 점이 글 쪽(데스크톱 왼쪽, 휴대폰 아래)에 오지 않게 한다. ② 화면 1(`problem`)이 이미 쓰는 방법(카메라와 목표점을 함께 옆으로 옮김)과 같다. 대상 장면: `about`(① project), `bubble`, `validation`, `limits`, `demo`, `contact`.
- 그래도 대비가 모자라면 캔버스(3D)나 대체 이미지 위에 **경계가 보이지 않는 넓은 방사형 어둠**을 글 쪽에 한 겹 둔다. 시안 `01`의 첫 화면이 쓰는 방식이다. 상자 모양·테두리가 보이면 안 된다.
- ② 수집 4단계 카드(`.collect-steps li`)와 데모 결과 상자, 탑승권 카드는 **내용 자체가 카드**인 부품이라 그대로 둔다(글 뒤 판이 아니다).

## 3. ③ 와플 설명 한 줄 (계획 6-1)

- 지금: 그룹마다 이름표 아래로 피처 이름 목록이 펼쳐져 옆 칸·글과 겹친다.
- 바꿈: 마우스를 올린(휴대폰은 누른) 그룹만 **호박색**, 나머지 그룹은 흐리게(알파 약 25%). 피처 이름은 와플 줄 아래 **한 곳의 설명 줄**에만 나온다: `그룹 이름 · 비율 · 피처 개수` + 피처 이름 목록. 아무것도 올리지 않았을 때 설명 줄은 비어 있거나 안내 문구(`features.hint`)를 보여 준다.
- 좁은 화면(와플 2줄)에서는 두 줄 전체 아래에 설명 줄을 둔다.
- 설명 줄은 그림 판 안(와플 아래)에 있다. §2의 자막 띠와 겹치지 않는다.
- 3D에서 "나머지 흐리게"는 배경 점에도 똑같이 적용해야 한다(와플은 3D 점으로 그려진다). 지금 `ChartLayout.group`은 지형 출발일 번호라 뜻이 다르므로, 배치에 **와플 그룹 번호를 따로** 두고(와플이 아닌 차트는 −1) 셰이더에 **강조 그룹 uniform**(`uFocusGroup`, 없음 = −1)을 더한다. 강조가 바뀔 때 배치를 다시 보내지 않으므로 5-2에서 미룬 "보이는 슬롯에 바로 써서 튐" 문제를 건드리지 않는다. 2D(3D 꺼짐)에서는 같은 규칙으로 다시 그린다.
- 접근성: 이번에는 마우스·누르기만 바꾼다. 키보드 초점과 `aria` 구조는 5-3(눌러 펼치기)에서 다시 짠다(`2026-09-25` 설계 §4.1). 화면 낭독용 숨은 목록은 그대로 둔다.

## 4. 밤의 공항 첫 화면 (계획 6-2)

### 4.1 무엇을 보여 주나

터미널 창가에서 밤 활주로를 보는 장면이다. 목표는 **"심플하면서 알차게"**(사용자 기준)다. 모든 것을 **빛**으로만 그리고 형체(실루엣·건물 모양)는 그리지 않는다.

| 요소 | 모양 | 색 |
|---|---|---|
| 활주로 가장자리등 | 작고 선명한 점 + 옅은 번짐, 멀수록 흐려짐(공기 원근) | 흰색 |
| 활주로 중앙등 | 더 작은 점, 끝 900m는 따뜻한 흰색 | 흰색 |
| 활주로 끝·시작 줄 | 점 한 줄 | 흰색·따뜻한 흰색(빨강·초록 쓰지 않음) |
| 유도로 가장자리등 + 연결 유도로 곡선 | 점 | 파란색(사이트 점 색 `#8FB8FF` 계열) |
| 계류장 조명탑 | 높은 점 + 땅까지 가는 옅은 기둥 선 + 바닥 빛 웅덩이 | 호박색 |
| 건물 | **형체 없이 창문 불빛 줄만** | 따뜻한 흰색 |
| 먼 도시 | 지평선의 작은 반짝임 | 따뜻한 흰색 |
| 경고등 | 관제탑 자리의 깜빡이는 불 **하나** | **빨간색 — 화면에서 유일한 빨간색** |
| 별 | 하늘의 아주 희미한 점, 느리게 반짝임 | 흰색 |
| 바닥 | 활주로·유도로 아스팔트가 불빛에 옅게 밝아짐, 활주로 표시(끝 줄무늬·착지 구역 막대·중앙 점선)가 비친 만큼만 희미하게 | — |
| 젖은 노면 | 바닥 불빛 아래로 짧게 번지는 반사 | 불빛과 같은 색 |

**움직이는 것**
- **신호 물결**: 몇 초마다 밝은 파동이 활주로 등을 따라 멀리 달려간다. 이름 `SIGNAL`과 이어지는 연출이다. 나중에 파동 밝기를 실제 데이터(출발일별 가격)로 바꿀 수 있게 만든다.
- **착륙하는 비행기**: 멀리서 착륙등(가는 가로 렌즈 플레어)을 켜고 내려와 접지한다. 항행등은 흰색만 쓴다.
- **진입등 섬광**: 활주로 끝 너머에서 활주로 쪽으로 달리는 섬광.
- **유도로를 천천히 지나가는 비행기**: 흰 불빛만.
- 카메라가 아주 느리게 떠다니고, 마우스를 따라 시점이 살짝 움직인다(시차).

**빼기로 한 것**(사용자 2026-09-28): 세워 둔 비행기, 관제탑 형체, 건물 실루엣, 낮은 안개, 유도로 표지판, 안내 차량, 창틀. 빨간색은 경고등 하나만, 초록색은 쓰지 않는다.

**하늘**: 거의 검은 남색(`#010206` → 지평선 `#0c1426`). 지평선에만 가는 빛 띠가 있고 따뜻한 도시 빛을 아주 약하게 둔다. 전체 비네트와 아주 옅은 필름 입자를 둔다.

### 4.2 스크롤 흐름 (채택: "A로 시작 → 내려앉은 뒤 지형")

1. **처음 — A(살짝 내려다봄)**: 눈높이 약 40m. 활주로가 화면 오른쪽 위로 비스듬히 깊게 펼쳐진다. 이름·키워드는 왼쪽 아래에 있다.
2. **첫 화면을 스크롤하는 동안 — B로 내려앉음**: 이름이 흐려지고, 카메라가 **같은 방향을 보며 눈높이 약 12m로 내려앉는다.** 활주로가 지평선의 빛 띠로 좁아지고 하늘이 넓어진다.
3. **① PROJECT로 넘어가며 — 지형으로**: 지평선의 불빛들이 떠올라 **가격 지형으로 모이고** 카메라가 지형을 보는 자리로 올라간다. 경고등과 움직이는 비행기·섬광·별은 사라진다. **창문·도시 불빛까지 모든 고정 불빛은 사라지지 않고 지형 점이 된다**(사용자 요청: "사라지는 불빛 없게").

"불빛이 곧 데이터"가 이 흐름의 메시지다. 활주로 불빛 하나하나가 지형의 신호 점이 된다.

### 4.3 로딩 화면

- 문구를 `NOW BOARDING`으로 바꾼다(사용자 2026-09-28). 세 언어 공통 영어.
- 화면 **가운데**에 크게: 작은 `NOW BOARDING` → 큰 숫자(`facts`의 필터 후 행 수, 플립 글자판 그대로) → 호박색 가는 진행선(CSS 애니메이션) → 작은 `ROWS`.
- 1.2초 고정 연출·재방문 생략·CSS만으로 사라짐 규칙은 그대로(`Loader.tsx`). 끝나면 활주로 불이 **앞에서 뒤로 차례로 켜진 뒤** 이름이 나타난다.

### 4.4 첫 화면 글 배치

- 이름·키워드·머리줄·오른쪽 아래 메타 글자가 화면 가장자리에 너무 붙어 있었다(사용자 지적). 좌우 여백을 `max(7vw, (100vw − 1280px) / 2)`로 통일하고, 첫 화면 글도 이 기준선에 맞춘다. 사이트의 다른 섹션(`.wrap`)과 같은 선에 서게 한다.
- 첫 화면 글 뒤 판(`.text-scrim`)은 없앤다(§2.1). 장면 구도가 왼쪽 아래를 비워 두고, 경계 없는 방사형 어둠을 한 겹 둔다.
- 오른쪽 아래 메타 글자 `ICN · 37.46°N 126.44°E` / `ICN ⇄ NRT · KIX · HND`를 시안대로 넣는다(좌표는 인천공항 실제 좌표). 숫자 직접 기입 금지 규칙에 따라 좌표와 공항 코드는 `facts.json`에 두고 조립한다. 휴대폰에서는 숨긴다.

### 4.5 구현 방식

- **같은 점 구름을 쓴다.** 새 캔버스를 만들지 않고 지금 `TerrainPoints`의 `Points` 하나에 **공항 목표 좌표 속성(`aAirport`)**을 더한다. 흩어짐·지형·지도·차트 목표와 같은 방식으로 uniform(`uAirport`)으로 섞는다.
  - 공항 불빛 개수(데스크톱 약 1,500개, 휴대폰은 절반)만큼의 **신호 점**을 공항 불빛 자리에 배정한다. 나머지 점은 공항 장면에서 알파 0이고 지형으로 넘어갈 때 떠오른다(지금 첫 화면의 "신호가 떠오르는" 연출과 같은 원리).
  - 불빛마다 색 번호(흰색·따뜻한 흰색·파랑·호박)와 크기를 속성으로 준다. 셰이더의 색 표(`toneColor`)에 흰색·따뜻한 흰색을 더한다.
  - 공항 배치는 **코드로 만든다**(활주로 길이·간격·곡선 규칙). 새 데이터 파일은 없다.
- **점이 아닌 것**은 같은 장면에 따로 작은 객체로 둔다: 바닥면(활주로·유도로 판 + 불빛 웅덩이, 가산 합성 텍스처), 활주로 표시, 별, 착륙·유도 비행기, 진입등 섬광, 경고등, 신호 물결(셰이더 uniform으로 가장자리·중앙등 밝기만 올림). 모두 지형으로 넘어갈 때 사라진다.
- **장면 표**(`scenes.ts`): `hero`를 공항 장면으로 바꾸고 진행도(`progress`)로 A → B 카메라를 보간한다(`bubble`의 `drop`과 같은 방식). ① `project`의 `about` 장면이 지형이다. 섹션 경계에서 기존 "부드럽게 다가가기"가 공항 → 지형 전환을 맡는다.
- **성능 예산**: 3D 청크 ≤250KB(지금 약 240KB)를 넘지 않아야 한다. 공항 배치 생성 코드·셰이더 추가분을 계획에서 먼저 재 보고, 넘으면 별·물결 같은 곁가지부터 줄인다. 초기 JS·LCP 규칙은 그대로(3D는 첫 화면 글 뒤 지연 로딩).
- **모바일**: 세로 화면은 기존처럼 더 물러난 카메라(`PORTRAIT_DISTANCE`), 글은 아래. 불빛 수는 절반.

### 4.6 대체 화면·공유 이미지

- 움직임 줄이기·WebGL 불가·저사양·지속 저프레임에서는 지금처럼 **정적 WebP**. `hero.webp`를 공항 장면(A 시점, 불 다 켜진 상태)으로 다시 캡처한다(`npm run fallbacks`).
- OG 이미지(`npm run og`)는 지금 지형이다. 공항 장면으로 바꿀지는 6-2 구현 뒤 두 장을 비교해 사용자가 정한다.

## 5. 다국어·문구

- 새 영어 연출 글자 `NOW BOARDING`은 세 언어 공통.
- 와플 설명 줄의 문구는 기존 `content/*.json`의 그룹 이름·단위를 쓴다. 새 문장이 필요하면 세 파일에 같은 키로 더한다(키 일치 테스트).
- 숫자 직접 기입 금지 규칙 그대로(행 수·비율은 `facts.json`).

## 6. 접근성

- 자막 방식에서 화면에 안 보이는 문단도 DOM에는 순서대로 있어 화면 낭독기는 모두 읽는다. 흐려짐 전환은 `opacity`만 쓰고 `display: none`이나 `aria-hidden`으로 숨기지 않는다.
- 캔버스·로딩 화면은 지금처럼 `aria-hidden`.
- 판을 없앤 뒤 글 대비를 axe와 눈으로 다시 확인한다(데스크톱·휴대폰, 3D 켜짐·꺼짐).

## 7. 테스트

- **6-1**: e2e — 그림 판 블록에서 글 상자와 그림 판 상자가 어떤 스크롤 위치에서도 겹치지 않는다(bounding box), 글 뒤 배경이 투명하다, 와플 그룹에 마우스를 올리면 설명 줄에 그 그룹 이름이 나오고 다른 그룹 이름표는 흐려진다, 기존 axe 검사 통과.
- **6-2**: 단위 — 공항 배치 생성(불빛 개수, 모든 불빛이 지형 점에 배정됨, 빨간색은 경고등 하나뿐), 장면 표의 A → B 보간. e2e — 로딩 화면에 `NOW BOARDING`, 첫 화면 → ① 스크롤 시 활성 장면 전환, 대체 이미지 모드에서 `hero.webp`. 용량 검사(`npm run size`) 통과.
