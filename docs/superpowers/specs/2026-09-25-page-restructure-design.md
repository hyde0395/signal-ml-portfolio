# 페이지 구성 개편 설계 (2026-09-25)

> 기존 설계 `2026-09-23-portfolio-design.md`의 §3(페이지 구성)을 바꾸는 문서다. 여기서 정하지 않은 것(비주얼 시스템, 다국어, 성능 목표, 배포, 접근성 원칙)은 기존 설계를 그대로 따른다.
> 시안(고른 것만, 브라우저로 바로 열림): `docs/superpowers/mockups/2026-09-25/` — `01-project.html`(① 시안 A), `02-data-flipboard.html`(② 실감 v3), `03-features.html`(③ 시안 A — 파일 안의 B는 고르지 않음), `04-charts.html`(④ 차트 4개). 시안 속 노선별 행 수·관측 편 수는 예시값이다(§5).

## 1. 왜 바꾸나

지금은 "소개 → 케이스 스터디 6챕터 → 데모 → 기술 스택" 순서의 글 중심 구성이다. 이것을 **프로젝트 → 데이터 → 피처 → 차트** 순서로 바꿔 ML 프로젝트의 흐름대로 읽히게 하고, 배경의 점을 실제 차트로 모이게 해서 "데이터로 말하는" 사이트로 만든다. 문구는 사용자가 나중에 전체적으로 바꿀 예정이라 이번에는 초안으로 채운다.

**섹션 머리표**: `01 — PROJECT`, `02 — DATA COLLECTION`, `03 — FEATURES`, `04 — CHARTS`(플립 글자판으로 넘어감, 기존 `GATE 0N — …` 자리). 세 언어 공통 영어. 번호는 §2.1 목록 순서로 자동.

### 2.1 섹션 목록 한 곳에서 관리 (나중에 섹션 추가 예정 — 사용자 요청)

무엇을 더할지는 아직 정해지지 않았다. 그래서 섹션 추가가 쉬운 구조로 만든다.

- **섹션 목록 파일 하나**(`src/lib/sections.ts`): 섹션마다 `id`, 머리표(`03 — FEATURES`의 영어 이름), 배경 장면 키(하나 또는 여러 개), 문구 키 접두어, 부품을 적는다. `HomePage`는 이 목록을 돌며 섹션을 그린다.
- **머리표 번호(01, 02…)는 목록 순서로 자동**으로 매긴다. 중간에 섹션을 끼워 넣어도 번호를 손으로 고치지 않는다.
- **옆 목차**: 데스크톱 화면 왼쪽 가장자리에 번호만 세로로 작게(`01 02 03 04`) 두고, 지금 보는 섹션을 호박색으로 표시, 누르면 그 섹션으로 이동한다. 이것도 목록에서 만들어진다. 휴대폰에서는 숨긴다(메뉴 버튼 없음 결정 유지).
- 새 섹션을 더할 때 할 일: 목록에 한 줄 + 섹션 부품 + (필요하면) `scenes.ts`에 장면 하나 + 문구 키. 테스트는 목록을 기준으로 돌아서 따로 늘리지 않아도 된다(머리표 순서, 장면 키 존재, 문구 키 존재).
- 나중에 한 페이지 스크롤이 아닌 별도 페이지(`/projects/<id>` 등)가 필요해지면 언어별 라우트 그룹(`app/(ko)` 등)에 페이지를 더하면 되도록, 섹션 부품은 `HomePage`에 묶이지 않게 만든다.

## 3. 섹션별 설계

### 3.1 ① PROJECT (시안 A)

- 큰 질문 `한·일 항공권, 언제 사야 할까?`(기존 `case.heading`), 설명 두 줄.
- 숫자 4개(호박색 IBM Plex Mono): **노선 수**(6), **수집 기간**(5개월, 매일 자동 수집), **피처 수**(33), **예측 구간 수준**(80%). 모두 `facts.json`에서 읽는다(`data.routes`, `data.collectStart`~`collectEnd`로 계산한 개월 수, `model.featureCount` 신규, `model.interval.level`).
- 배경은 첫 화면 지형이 그대로 이어지고 카메라만 조금 움직인다(기존 `about` 장면 자리).

### 3.2 ② DATA COLLECTION (시안 C 실감 v3)

**수집 라인**: 가로 4단계 `COLLECT`(SerpApi · Google Flights 검색 결과) → `SCHEDULE`(GitHub Actions · 매일, 먼 출발일 주 1회) → `FILTER`(무결성·직항 확인, 원본 행 → 필터 후 행) → `JOIN`(원/엔 환율 · 공휴일 · 유가). 휴대폰에서는 세로.

**플립 보드**:

- 머리줄 `DEPARTURES` + 언어별 작은 부제(ko "수집 현황") + 오른쪽 `수집 시작 → 수집 끝 · N DAYS`.
- 열: `ROUTE` · `DESTINATION` · `ROWS` · `STATUS`. 줄: **왕복을 한 줄로 합친 3개 노선** `ICN⇄NRT NARITA` / `ICN⇄KIX KANSAI` / `ICN⇄HND HANEDA` + `TOTAL`. 행 수는 **필터 후** 값(가는 편+오는 편), 합계는 `data.filteredRows`와 일치해야 한다(테스트로 검사).
- 상태: 초록 불 + `DAILY`.
- 칸 디자인: 금속 테두리와 모서리 나사가 있는 보드, 칸마다 위/아래 반쪽과 가운데 경첩 선(경첩 핀은 넣지 않음 — 사용자 요청). 위 날개가 0→−90° 접히고 아래 날개가 90→0° 펴진다. 글자는 정해진 순서(` A–Z 0–9 , . - ⇄`)로만 넘어간다.
- 크기: 데스크톱 칸 44×66px·글자 42px. 휴대폰 칸 19×30px, `DESTINATION` 열과 `STATUS` 글자를 숨기고 불빛만 남긴다(390px 폭에서 가로 스크롤 없음 — 시안에서 확인).
- **모션 예외(사용자 승인)**: 이 보드만 기존 플립 규칙(글자당 40ms, 전체 0.8초, 튕김 금지)의 예외다. 한 번 넘기는 데 약 60ms, 칸마다 최대 14번(목표 글자 14칸 앞에서 출발), 칸 사이 5ms 지연 → **전체 약 2초**. 아래 날개가 펴질 때 살짝 튕긴다(`cubic-bezier(.3,1.5,.6,1)`). 화면에 들어올 때 한 번 돈다.
- 달깍 소리는 넣지 않는다(시안에만 있던 선택 기능).
- 화면 낭독기: 보드는 표(`<table>`)이고 칸 글자는 `aria-hidden`, 셀마다 완성값을 읽는다. reduced-motion·대체 화면에서는 완성값만 바로 보인다.
- 기존 `src/motion/flip.ts`(글자판 텍스트 플립)와는 별개의 부품으로 만든다(3D 날개 구조가 다름). 둘 다 같은 글자 순서를 쓴다.

**배경**: 기존 3-1 `problem` 장면(한·일 해안선 + 노선 궤적, `map: 1`)을 ② 뒤로 옮긴다.

### 3.3 ③ FEATURES (시안 A)

- 제목 `33 FEATURES` + 한 줄 설명.
- 배경 점이 날아와 **6개 덩어리**로 모인다. 덩어리 크기(점 개수) = 그룹 중요도(XGBoost gain 그룹 합계), 점 하나 ≈ 0.1%. 공휴일만 호박색.

| 그룹 | gain | 피처 수 | 피처 |
|---|---|---|---|
| lookup 통계 | 46.8% | 13 | rd_med/min/max/std, rah_med/std, ra_med/std, rm_med/std, r_med/std, global_med |
| 노선·항공사 | 26.0% | 5 | origin, destination, route, airline, airline_class |
| 공휴일 | 11.4% | 4 | is_kr_holiday, is_kr_near_holiday, is_jp_holiday, is_jp_near_holiday |
| 남은 일수 | 6.8% | 4 | days_to_departure, log_days, days_sq, days_bucket_num |
| 항공편 정보 | 4.6% | 5 | stops, duration_minutes, departure_hour, is_weekend_flight, departure_month |
| 시장 | 1.2% | 2 | krw_jpy_rate, fuel_tier |

- 덩어리 위에 중요도 %·그룹 이름, 아래에 피처 개수(HTML 라벨을 3D 위치에 맞춰 겹침). 피처 이름은 **마우스를 올리면(휴대폰은 누르면)** 덩어리 아래에 나온다. 키보드로도 덩어리마다 초점을 줄 수 있어야 한다.
- 화면 낭독기와 대체 화면용으로 같은 내용을 목록(그룹 · % · 피처 이름)으로 문서에 둔다(시각적으로 숨김).
- 작은 글씨로 "lookup 중요도는 노선·항공사 정보를 나눠 가진 몫이라 실제보다 크게 나온다"를 표기한다.
- 휴대폰: 덩어리를 두 줄로 나누고 라벨이 겹치지 않게 한다.

### 3.4 ④ CHARTS

차트 하나가 화면 한 장을 차지한다(데스크톱: 차트 크게 + 옆 글 카드, 휴대폰: 차트 위 + 아래 글 카드 — 기존 챕터 카드 배치와 같음). 스크롤로 다음 차트에 들어가면 점들이 다음 모양으로 이동한다. 모든 차트는 **점 하나하나가 실제 데이터**인 모양이어야 한다(점을 쌓아 만든 막대그래프는 사용자가 "별로"라고 해서 뺐다).

| # | 차트 | 점이 나타내는 것 | 강조 |
|---|---|---|---|
| 1 | **출발일별 가격 — 공휴일 봉우리** | 출발일(180개)마다 노선·등급 평균 대비 % 만큼의 세로 점 기둥 | 공휴일 ±3일 기둥은 호박색. 추석·연말연시·설 이름표 |
| 2 | **U자 예약 곡선** | 출발이 지난 편의 관측 하나 = 점 하나(x=출발까지 일수 90→1, y=같은 편 평균 대비 %, ±22% 밖은 그리지 않음) + 날짜별 평균을 이은 밝은 선 | 가장 싼 구간(D-21~60) 관측은 호박색 |
| 3 | **R² 거품 빼기** | 예측값 대 실제값 산점도 + 대각선 | 잘못 매칭된 9,387행(호박색)이 모였다가 아래로 떨어져 사라짐. 옆에 `R² 0.84 → 0.64`, `MAE 48,442 → 48,235원` |
| 4 | **예측 구간** | 기준일 인천→나리타 LCC, D+3~90: 흐린 세로 점 = q10~q90, 밝은 점 = 예측가 | 공휴일 출발일은 호박색 |

- 차트 3 뒤에 기존 평가 방식 표(`ValidationTable`)와 글을 둔다. 마지막에 "한계와 다음 단계" 글(단순 기준선 MAE와 모델 MAE가 거의 같음, 추천 92.1% 지금 구매, 다음 단계)을 둔다. 이 둘은 차트로 만들지 않는다.
- 축 이름·눈금·이름표·수치는 **HTML 글자**로 겹친다(3개 언어, 화면 낭독기). 차트마다 한 줄 요약을 `aria-label`/설명 문단으로 둔다.
- 차트마다 "코드 보기" 링크(기존 `codeLinks.paths` 재사용: insight → 차트 2, bubble → 차트 3, interval → 차트 4, 차트 1은 공휴일 피처가 정의된 `src/processing/features.py`). ②·③에도 섹션당 하나(② `problem` 경로, ③ `src/processing/features.py`). 경로 키 이름은 새 섹션에 맞춰 바꾸고 `facts.json` 한 곳에만 둔다.

## 4. 3D 구현 방식 (승인: 방식 1)

**같은 점들이 차트 모양으로 이동한다.** 배경의 `Points` 하나(현재 신호 약 2,070 + 잡음 약 24,500 + 제거 레이어 9,387)에 장면별 **목표 위치**를 더 주고, 스크롤 진행도에 따라 셰이더가 옮긴다. 지형 → 지도 접기와 같은 원리다. 검토한 다른 방식(2D 캔버스로 차트를 따로 그리고 배경은 흐리게 / 3D는 대략 모양, 정확한 선은 2D)은 "배경 점이 차트가 된다"는 요구에 못 미쳐 고르지 않았다.

- **목표 위치 배정**: 차트마다 필요한 점 수만큼 기존 점을 배정하고, 남는 점은 흐리게 가라앉힌다(불투명도 0 가까이). 차트 3의 호박색 점은 원래 제거 레이어(9,387행) 점을 쓴다 — 기존 `removed`/`drop` 연출을 그대로 살린다.
- **카메라**: ③·④는 정면에서 평평하게 보는 시점(차트는 xy 평면). 장면 표(`scenes.ts`)에 `features`, `chart1~4`를 더하고, 세로 화면 전용 값도 둔다.
- **목표 위치 계산 위치**: 점 좌표를 JSON에 미리 넣지 않고, 작은 데이터(`charts.<ver>.json`: 출발일별 %, 관측 표본, 산점도 표본, 예측 구간)를 받아 사이트에서 계산한다. 3D 청크 예산(256,000B, 현재 약 240.8KB)이 빠듯하므로 차트 배치 코드는 3D 청크 밖의 별도 지연 청크로 두거나 가볍게 유지하고, `npm run size`로 확인한다. `charts.json` 예산은 gzip 150KB로 새로 정한다.
- **HTML 라벨 정렬**: 3D 좌표를 화면 좌표로 바꿔 라벨 위치를 맞추는 작은 모듈을 둔다(카메라가 멈춘 뒤 한 번 계산, 크기 바뀔 때 다시).
- 장면 선택은 기존 `activeScene.ts`의 "뷰포트 가운데를 포함한 가장 짧은 요소" 규칙을 그대로 쓴다. `data-chapter` 대신 `data-scene`으로 이름을 통일한다.

### 4.1 인터랙션 (사용자 선택 2026-09-25)

고른 것: **점이 마우스에 반응**, **차트 직접 만지기**. (고르지 않은 것: R² 거품 스위치, 플립 보드 ↔ 지도 연결 — 필요하면 나중에.)

#### 점이 마우스에 반응

- 지금은 첫 화면만 반응한다. 이것을 **모든 장면**으로 넓힌다. 포인터 위치를 장면 평면에 투영해 셰이더 uniform으로 넘기고, 반경 안의 점을 바깥으로 살짝 밀었다가 포인터가 떠나면 제자리로 돌아온다(이징은 expo.out, 튕김 없음). 차트 장면에서는 미는 거리를 줄여 차트 모양이 읽히게 한다.
- 휴대폰(터치): 계속 밀어내면 스크롤을 방해하므로, 누른 지점에서 한 번 퍼지는 물결만.
- **③ 피처 덩어리 펼치기**: 덩어리를 누르면(또는 초점 후 Enter/Space) 그 덩어리의 점이 **피처별 작은 덩어리**(그룹 안 피처 수만큼, 크기 = 피처별 gain)로 갈라지고 피처 이름표가 붙는다. 다른 덩어리는 흐려진다. 다시 누르거나 Esc로 닫는다. 한 번에 하나만 펼친다. 피처별 gain이 필요하다(§5).
- reduced-motion·대체 화면에서는 반응하지 않는다. 펼치기는 대체 화면에서 목록(그룹별 피처 이름과 %)으로 대신한다.

#### 차트 직접 만지기

| 차트 | 조작 | 보여 주는 것 |
|---|---|---|
| 1 출발일별 가격 | 마우스를 올리면 가장 가까운 출발일 기둥이 밝아지고 세로 안내선 | 출발일(요일), 평균 대비 %, 공휴일이면 이름(3개 언어, 기존 공휴일 이름표 재사용) |
| 2 U자 곡선 | 세로선(`D-N`)을 좌우로 끈다. 처음 위치는 가장 싼 날 | "D-N에 사면 같은 편 평균보다 ±X%", 그 날의 관측 수 |
| 3 R² 거품 | 조작 없음(떨어지는 연출만) | — |
| 4 예측 구간 | 마우스를 올리면 가장 가까운 출발일의 띠가 밝아짐 | 출발일, 예측가, q10~q90 금액 |

- **구현**: 점 하나하나를 GPU에서 고르지 않는다. 차트 배치를 계산한 JS 함수가 그대로 있으므로, 포인터 화면 좌표 → 차트 좌표(§4의 3D↔화면 좌표 변환 모듈의 역변환)로 바꿔 가장 가까운 x 값을 찾는다. 강조는 셰이더 uniform(강조할 x 범위) 하나로 한다.
- **키보드**: 차트에 초점(Tab)을 주면 ←/→로 한 칸, Home/End로 처음/끝. 차트 2의 세로선은 `role="slider"`(값 = 일수, 읽는 값 = "D-N, 평균 대비 X%"). 차트 1·4는 초점 안의 현재 항목을 읽는다. 조작을 멈춘 뒤 한 번만 알린다(데모 막대와 같은 규칙).
- **터치**: 누르고 끌면 마우스 올리기와 같다. 세로 스크롤과 헷갈리지 않게 가로로 먼저 움직일 때만 차트 조작으로 잡는다.
- 표시 상자(툴팁)는 HTML, 3개 언어. 차트 밖으로 나가지 않게 위치를 맞춘다.
- 대체 화면: 정적 이미지 + 요약 글. 조작 대신 차트 아래에 주요 값 몇 개(가장 비싼/싼 출발일, 가장 싼 D-N)를 글로 둔다.

## 6. 콘텐츠와 다국어

- 새 키: `project.*`, `data.*`(수집 라인 4단계, 보드 부제·열 이름 부연), `features.*`(그룹 이름 6개, 설명, lookup 주의 문구), `charts.c1~c4.*`(제목·요약·축 이름·글), `charts.validation.*`(기존 표 문구 이동), `charts.limits.*`(기존 한계 문구 이동), `contact.about.*`(기존 `about.*` 이동). 세 파일 키 일치 테스트와 숫자 직접 기입 금지 테스트를 그대로 적용한다.
- 없어지는 키: `about.*`(이동), `case.<chapter>.*`(이동·삭제), `stack.*`.
- 문구는 기존 문장을 최대한 옮겨 쓰고, 새 문장은 한국어 초안 → 영·일 초안. 사용자가 나중에 전체 문구를 바꾼다.

## 7. 접근성·대체 화면

- 대체 화면(reduced-motion, WebGL 불가, 저사양, 지속 저프레임)에서는 ③ 덩어리와 ④ 차트 4개를 **정적 WebP**로 보여 준다. `capture-fallbacks.mjs`에 `features`, `chart1~4` 장면을 더하고, 없어지는 `insight`·`interval` 대체 이미지는 지운다(`problem` 이미지는 ② 배경으로 계속 씀).
- 모든 차트와 덩어리는 같은 내용을 글(요약 문단 또는 숨긴 목록)로도 제공한다. 색만으로 뜻을 전하지 않는다(공휴일은 이름표, 차트 3의 떨어지는 점은 글로 설명).
- 플립 보드는 §3.2대로.

## 8. 테스트

- 단위: 섹션 목록(머리표 번호 자동, 장면·문구 키 존재), 차트 목표 위치 계산(점 수, 범위, 공휴일 색), 3D↔화면 좌표 변환과 가장 가까운 x 찾기, 피처 펼치기 배치, 보드 글자 순서·넘김 횟수 상한, `byRoute` 합계 = `filteredRows`, 새 콘텐츠 키.
- 추출 스크립트 pytest: `charts.json` 형식, 관측 편 수가 `realizedFlights`와 같은지.
- e2e: 새 섹션 순서와 머리표, 보드 완성값(모션 끔), ③ 덩어리 초점·피처 이름 표시, ④ 차트 전환 시 장면 키, 차트 1·4 마우스 올리기 표시 상자, 차트 2 슬라이더 키보드 조작과 낭독 값, ③ 덩어리 펼치기/Esc 닫기, 옆 목차 이동, 대체 화면에서 이미지 5장 이상, axe 통과, 휴대폰 폭 가로 스크롤 없음.
- 용량: 초기 JS 150KB, 3D 청크 256,000B, `charts.json` 150KB(gzip).
