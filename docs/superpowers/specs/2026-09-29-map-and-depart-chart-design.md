## 1. 지도 — 가는 실선 (② 화면 1 `problem`, 화면 2 `dataBoard`)

원인: 점 약 2만 8천 개를 해안선 샘플 4,208곳에 나눠 넣고 ±0.03씩 흔들어 같은 자리에 겹겹이 쌓인다(굵고 흐릿한 띠). 잡음 점은 모이는 비율이 0.9라 해안선 둘레에 뿌옇게 남는다. 노선 궤적도 흔들린 점이라 굵다.

- **해안선**: `map.v1.json`의 해안선을 이어진 선분끼리 나누고(점 사이가 0.5도보다 멀면 새 선 — 섬·대륙이 선으로 이어지지 않게), 세계 좌표에서 **같은 간격(0.035)** 으로 다시 뽑는다. 약 2,800점. 흔들림 없음.
- **노선**: 3개 노선마다 호를 같은 간격으로 170점(높이는 지금처럼 가운데 1.5). 흔들림 없음.
- **배정**: 점 구름의 앞쪽부터 해안선 → 노선 순서로 자리를 준다(신호·잡음 구분 없이). 남는 점은 **지도 장면에서 숨긴다** — 점마다 "지도에 쓰는 점인가"를 기존 `aRoute` 속성에 담는다(1 노선, 0 해안선, **−1 안 씀**). 정점 속성은 이미 14개라(WebGL 공통 한계 16) 새 속성을 더하지 않는다.
- **밝기·크기**: 지도 장면에서는 종류(신호·잡음)와 상관없이 같은 알파(해안선 0.8, 노선 0.9)와 작은 크기(지형 신호 점의 약 60%)로 그린다 — 선의 굵기가 고르게. 거리 흐림(6-3 D)은 지도에도 그대로.
- **모이기**: 지도 장면에서는 잡음 점도 끝까지 모인다(모이는 비율 0.9 → 지도 비율만큼 1로). 뿌연 둘레가 없어진다.
- 지형 → 지도로 넘어갈 때 안 쓰는 점은 옮겨 가며 사라지고, 지도 → 지형으로 돌아오면 다시 나타난다(`uMap`으로 부드럽게).
- 화면 2(`dataBoard`, 멀리서 흐리게 `dim 0.16`)도 같은 점을 쓰므로 함께 깔끔해진다.
- 휴대폰(잡음 점 절반, 약 1만 5천 점)도 해안선·노선에 필요한 점(약 3,300)보다 충분히 많다.

## 2. 출발일 차트 — 시간 흐름 점 그래프 + 요일 평균 (④ 차트 1 `chartDepart`)

- **점 그래프(판 왼쪽 약 74%)**: 가로 = 출발일(실제 날짜 간격 — 수집이 드문 먼 출발일은 성기게 보인다), 세로 = 노선·등급 평균 대비 %(−30 ~ +75). 출발일 하나 = 작은 점 뭉치 하나(지금처럼 그 출발일의 배경 점들이 모인다 — `group` = 출발일 번호). 0% 기준선과 +50·+25·−25 옅은 점선, 왼쪽 눈금(%), 아래 월 이름.
  - 세로 막대로 쌓지 않는다(점 막대그래프는 사용자가 전에 "별로"). 줄기 선도 없다(시안에서 지저분했다).
- **요일 평균(오른쪽 약 23%)**: 요일 7줄(월~일), 0을 가운데 둔 가로 점 줄 — 줄 길이 = 그 요일 출발일의 평균 대비 %, 끝에 값(`+20%`). 평균이 +15% 넘는 요일(지금 데이터: 일)은 호박색. 값은 `charts.json`의 출발일 데이터로 사이트가 계산한다(새 데이터 없음).
- **호박색 규칙 바꿈**: "공휴일 ±3일"이 아니라 **공휴일 ±3일이면서 평균보다 25% 이상 비싼 출발일**만. 지금은 ±3일을 모두 칠해(마린데이·경로의 날 등) 강조가 흐려졌다. 기준값 25는 상수 한 곳.
- **공휴일 이름표**: 그 출발일 점 뭉치 **바로 위**에 가운데 맞춤. 공휴일(코드)마다 가장 비싼 출발일, 큰 순 **4개**(지금 3개 → 한글날이 더해진다). `export_charts.py`의 `TOP_LABELS`를 4로 바꾸고 `npm run charts`로 다시 뽑는다. 4번째 공휴일 이름이 3개 언어 문구에 있는지 `charts-content` 테스트가 지킨다(없으면 `charts.holidays`에 더한다).
- **좁은 판(휴대폰)**: 점 그래프가 판 전체 폭(위쪽 약 68%), 요일 평균은 그 아래 한 줄에 7칸(요일 이름 + 값 + 짧은 점 줄). 출발일 180개가 좁은 폭에 겹치므로 점 뭉치를 작게(반지름 줄임).
- **2D 대체 그림**은 같은 배치를 그린다(지금 구조 그대로).
- **문구(3개 언어)**: `charts.depart.body1`·`alt`를 새 그림에 맞게 — "점 하나가 출발일 하나이고, 클수록 …" → "점 하나가 출발일 하나이고, 위로 갈수록 노선·등급 평균보다 비쌉니다. 오른쪽은 요일별 평균입니다. 공휴일 무렵(호박색)과 일요일 출발이 가장 비쌉니다." 수치는 문구에 쓰지 않는다(숫자 직접 기입 금지 테스트). 영·일은 같은 뜻으로.
- 5-3b(차트 직접 만지기)의 차트 1 조작은 이 새 그림 위에서 한다 — 마우스를 올리면 가장 가까운 출발일 강조 + 표시 상자(점 그래프의 가로 위치로 찾기가 달력보다 쉽다).

## 3. 테스트

- 단위: 해안선 다시 뽑기(선 나누기, 같은 간격, 점 수 범위), 지도 배정(해안선 → 노선 → 안 씀, `aRoute` −1/0/1), 점 그래프 배치(출발일마다 뭉치, 세로 위치 = %, 호박색 = 공휴일 ∧ ≥25%, 이름표가 뭉치 바로 위, 요일 평균 값 = 데이터 평균, 좁은 판 배치), 기존 달력 테스트 교체.
- e2e: 기존 차트·지도 e2e가 새 배치로 통과(이름표 개수 검사: 달력 요일 7 → 요일 평균 7 + 눈금 등 새 기준으로 고침), 3D 켜짐 대비 화소 검사, axe.
- 눈 확인(실제 GPU): 지도 화면 1·2, 차트 1 데스크톱·휴대폰, 지형 ↔ 지도 전환.
- 대체 이미지: `problem.webp` 다시 캡처. OG는 첫 화면이라 영향 없음.

## 구현 결과 (계획 6-4)

- **지도**: 해안선 4,208 샘플이 0.5도 끊김 기준으로 34개 선이 되고, 0.035 간격으로 다시 뽑아 **2,820점**. 노선 3개 × 170점 = 510점(원본 샘플 사이를 보간 — 반올림 인덱스로 뽑으면 약 20점씩 겹쳐 밝게 뭉쳤다, 검토). 데스크톱 28,176점 중 24,846점, 휴대폰 15,926점 중 12,596점이 지도에서 숨는다. 제거 레이어(맨 뒤)는 모두 숨는다. `MAP_LINE`(0.035·170·0.5)·`MAP_POINT`(0.8·0.9·0.55)는 조정 없이 시안 C와 거의 같았다(선 굵기 약 3px 대 시안 2.6px). 공항 흰 점(시안에 있던 것)은 넣지 않았다.
- **차트 1**: `departLayout`(`DEPART` 값 그대로). 구현하며 바꾼 것: 요일 평균 이름 자리(`W*0.78+16`)와 점 줄 시작(`+64`) — 음수 값이 요일 이름에 붙었다. 좁은 판 오른쪽 끝 `W−14` — 설날 이름표가 화면 밖으로. 공휴일 이름표는 옆 이름표와 가로로 겹치면 한 줄(13px) 위로(글자 폭은 글자 수 × 6.6px로 어림), 판 위 8px에서 멈춘다. 월 이름은 앞 월 이름과 34px보다 가까우면 뺀다(좁은 판에서는 한 달 건너 표시).
- **이름표 4개**: 4번째는 한글날(2026-10-09, +42.4%). `charts.json`은 `labels`만 바뀌었다. 차트 1의 영·일 공휴일 이름은 짧게(Christmas·New Year's Day·Seollal·Hangul Day / クリスマス·元日·ソルラル·ハングルの日) — 긴 이름("Christmas (Korea)" 등)이 서로·요일 평균과 겹쳤다. 데모의 이름(`demo.holidays`)은 그대로.
- **문구**: 요일 평균 위치가 데스크톱은 오른쪽, 휴대폰은 아래라 "오른쪽은 요일별 평균" 대신 "요일별 평균도 함께 보여 줍니다"(3개 언어).
- 설계의 +50·+25·−25 옅은 점선은 넣지 않았다(0% 기준선만, 계획대로) — 눈금 글자로 충분했다.
- 검사: 단위 304개, e2e 184개(차트 1 눈금 이름표 18개), 초기 JS 141.7KB, 3D 청크 244.8KB, `problem.webp` 19KB(전 38KB). 실제 GPU 눈 확인: 지도 화면 1·2·전환, 차트 1 데스크톱·휴대폰·가로 휴대폰(844×390)·340px 영어.
- 알려진 것: 휴대폰 지도는 전처럼 글 뒤로 비친다(대비 검사 통과). 가로 휴대폰(844×390)에서 차트 자막 띠가 그림 아래쪽에 가깝게 붙는다(이번 변경과 무관, 6-1 배치).
