## 0. 목표

- ⑤ "검증 설계": 세 평가 방식(K-Fold · GroupKFold · TimeSeriesSplit)이 **데이터를 어떻게 나누는지**를 실제 수집 행 점으로 보여 준다.
  글만으로는 "K-Fold는 미래로 과거를 맞힌다", "GroupKFold는 처음 보는 출발일", "TimeSeriesSplit은 과거 → 미래"가 잘 읽히지 않는다.
- ② "걸러내기": 원본 행 중 무엇을 왜 걸렀는지를 **소요 시간 × 가격 산점도**로 보여 준다. 직항인데 경유 수준의 소요 시간인 무리가
  따로 떨어져 있는 것이 보이고, 그것이 ⑤ 차트 3("그 행들이 R²를 부풀렸다")으로 이어진다.
- 문구는 담백하게(사용자 톤). 수치는 facts만.

## 1. 사용자 결정 (2026-09-30)

| # | 정한 것 |
|---|---|
| 1 | ⑤ 검증 설계는 **세 방식을 차례로**(자막 칸 K-Fold → GroupKFold → TimeSeriesSplit). 점 = 실제 수집 행, 가로 = 수집일, 세로 = 출발일(시안 승인) |
| 2 | TimeSeriesSplit 칸에서는 폴드가 **저절로** 1 → 5로 넘어가 5/5에서 멈춘다(약 1.2초 간격). 스크롤 한 칸 안에서 끝난다 |
| 3 | 판 오른쪽 위에 그 방식의 R²·MAE를 **플립**으로. 세 방식을 나란히 보는 **표는 블록 뒤에 작게 남긴다** |
| 4 | ② 걸러내기와 ⑤ 차트 3은 **역할을 나눈다**: ②는 "무엇을 걸렀나", 차트 3은 지금처럼 "그게 R²에 준 영향"(9,387행 레이어 떨어짐 유지) |
| 5 | ② 걸러내기는 지도 없이 **A. 소요 시간 × 가격 산점도**. 규칙이 하나씩 적용되며 걸린 점이 호박색 → 떨어짐 |
| 6 | 섹션 사이 장면 틈 수정은 따로 먼저(PR #21) |

## 2. 사실 확인 (항공권 저장소, 2026-09-22 기준 — 추출 전 실측)

- 필터 순서(`export_facts.apply_filters` = `tscv_eval_v2.load_data`): ① `duration_minutes` 없음·400분 초과 또는 가격 3만 원 미만 →
  ② 출발·도착 시각차와 소요 시간이 30분 넘게 어긋남(`drop_inconsistent_flight_times`) → ③ 직항인데 노선별 직항 p05 + 65분 초과
  (`drop_implausible_direct_flights`).
- 행 수: 원본 258,829 → ① 5,742(400분 초과 5,731 + 가격 11) → ② 826(모두 하네다 노선) → ③ 9,387(5개를 빼면 모두 하네다) → 242,874.
- ①을 지난 행은 모두 `stops = 0`(직항)이다. 정상 행 소요 시간은 노선 직항 p05 기준 −5 ~ +35분 안(1~99%), ③ 행은 260 ~ 400분,
  ① 400분 초과 행은 중앙값 665분(90%가 1,085분 아래).
- 평가 방식(`tscv_eval_v2.py`): 행을 수집 시각(`fetch_timestamp`)으로 정렬한 뒤 — K-Fold `KFold(5, shuffle=False)`(연속 구간 5개,
  평가 구간 앞뒤가 모두 학습), GroupKFold `GroupKFold(5)` 그룹 = 노선 + 출발일, TimeSeriesSplit `TimeSeriesSplit(5)`
  (평가 구간 각 40,479행, 첫 평가 구간 06-19 ~ 07-08 … 마지막 09-03 ~ 09-22).
  시안에서 설명한 "K-Fold는 무작위로 흩어짐"은 틀렸다 — 실제는 가운데 시간 구간 통째가 평가다(시안은 실제대로 고침).
- 폴드별 R²는 저장소 문서에 범위(0.49 ~ 0.73)만 있다. 판에는 방식별 평균(facts `model.kfold`·`gkfNoLookup`·`tss`)만 쓴다.

## 3. 데이터

### 3.1 `facts.json`

- `data.filter`: `{ "unit": 5742, "mismatch": 826, "direct": 9387, "durationMax": 400 }` — `export_facts.py`가 `apply_filters`와 같은

  `rawRows − unit − mismatch − direct = filteredRows`.
- `codeLinks.paths.filter`: `blob/main/src/processing/features.py`(② 걸러내기 "코드 보기").

### 3.2 `charts.json` — `filter` (② 걸러내기)

- 표본: 기준일까지의 원본 행(①~③ 적용 전)에서 고정 시드로 **4,000행**, 실제 비율 그대로(① 약 89 · ② 약 13 · ③ 약 145).
  `duration_minutes`가 없는 행은 그릴 수 없어 표본에서 뺀다(① 안의 개수는 facts가 그대로 센다).
- 형식(정수, 원 단위 없음):
  ```json
  "filter": { "dur": [/* 소요 분 */], "pct": [/* 노선·등급 평균 대비 %×10 */], "rule": [/* 0 통과, 1 단위·소요, 2 시각 불일치, 3 직항 확인 */] }
  ```
  `pct`의 기준은 정상 행(242,874)의 노선·등급 평균(`export_terrain.add_route_class_pct`와 같은 정의). 걸린 행도 같은 기준으로 잰다.

### 3.3 `charts.json` — `split` (⑤ 검증 설계)

- 표본: 정상 행(242,874)을 수집 시각으로 정렬(안정 정렬)한 뒤 폴드를 **전체 행에서** 배정하고, 고정 시드로 **4,000행**을 뽑는다.
- 형식:
  ```json
  "split": {
    "fetch": [/* 수집일 번호: 수집 시작일(data.collectStart)부터 날짜 수 */],
    "date": [/* charts.dates 번호(출발일) */],
    "kf": [/* 0..4 */], "gkf": [/* 0..4 */], "tss": [/* -1(첫 학습 구간만) 또는 0..4 = 평가로 쓰인 폴드 */],
    "fetchDays": 153,
    "show": { "kf": 2, "gkf": 0 }
  }
  ```
  `show`: 판에 보여 줄 폴드. K-Fold는 가운데(2 = 07-16 ~ 08-08, 앞뒤 학습이 모두 보인다), GroupKFold는 0.
- 모델 재학습·예측은 없다(폴드 배정만). 가격 값은 없다.
- 다른 키는 한 글자도 바뀌지 않아야 한다(재생성 뒤 비교, 7-2와 같은 검사). gzip 한도 150KB 안(지금 23KB + 두 블록 약 20KB 예상).

### 4.1 ② 걸러내기 판 `chartFilter`

- 자리: ② 화면 1(`.data-intro`, 지도)과 화면 2(`.data-board`, 보드) 사이. 흐름 = 모음(지도) → 거름(이 판) → 결과(보드 합계).

- 축: 가로 = 소요 시간 60 ~ 960분(눈금 120·240·360·480·720분), 960분 초과 행은 판 오른쪽 끝 **"960+" 칸**(폭 약 4%)에 좌우로 흩어 둔다
  (칸 이름표 있음 — 줄로 붙지 않게). 세로 = 노선·등급 평균 대비 %(−90 ~ +300, 눈금 −50·0·+100·+200). 축 이름 두 개.
- 규칙 이름표(세 언어 공통 영어, 판 오른쪽 위 세로 목록): `RULE 1 · DURATION · UNIT`, `RULE 2 · TIME MISMATCH`, `RULE 3 · DIRECT CHECK`.
  적용된 규칙은 호박색 ●, 아직은 흐린 ○. 아래에 행 수 이름표(플립): `258,829 ROWS` → 마지막에 `242,874 ROWS`.
- 규칙 선: 규칙 1 = 세로 점선(400분)만 — 가격 하한(3만 원)은 노선마다 %가 달라 선 하나로 그릴 수 없고 해당 행도 11개뿐이라
  점만 호박색으로 켠다. 규칙 2는 선이 없다(소요 시간은 정상처럼 보이고 시각이 어긋난 행이라 제자리에서 켜진다).
  규칙 3 = 점선 상자(직항 기준 + 65분부터 400분까지, 세로 전체) + 이름표 `data.filter.boxLabel`("직항인데 경유만큼 걸림").

  | 단계 | sub 0 | sub 1 |
  |---|---|---|
  | 0 모은 행 | 모든 점 파랑 | — |
  | 1 규칙 ①·② | 규칙 1 선 + ①·② 점 호박색(제자리) | ①·② 점이 판 아래로 떨어짐(아래 밖, 알파 0) |

### 4.2 ⑤ 검증 설계 판 `chartSplit`

- 자리: ⑤ 차트 3(bubble) 다음, 지금 `EVALUATION` 글 카드 자리. 머리표 `EVALUATION`(플립), 제목 h3 `charts.validation.heading`("검증 설계").
- 축: 가로 = 수집일(매달 1일에 월 이름), 세로 = 출발일(두 달마다 월 이름, 1월에는 해도 — 차트 1의 월 이름 함수를 재사용),
  축 이름 `axisX`·`axisY`.
- 색: 학습 = 파랑(TONE.dot), 평가 = 호박(TONE.amber), 아직 안 씀(TSS에서 평가 구간 뒤) = 흐린 파랑(알파 0.25). 범례(판 오른쪽 아래).
- 수치 이름표(판 오른쪽 위, 휴대폰은 판 왼쪽 위): 방식 이름(영어), `R² 0.668`, `MAE 44,196원`(단위는 언어별 `charts.validation.table.maeUnit`),
  짧은 설명 한 줄(`charts.validation.tagKf`/`tagGkf`/`tagTss` — "참고 상한", "처음 보는 출발일 · lookup 없이", "운영 기준"). 단계가 바뀌면 플립.
  TSS 단계에서는 그 아래 `FOLD n / 5`.
- 단계(자막 칸 3개):
  | 단계 | 점 |
  |---|---|
  | 0 K-Fold | `kf == show.kf` 평가, 나머지 학습 |
  | 1 GroupKFold | `gkf == show.gkf` 평가, 나머지 학습 |
  | 2 TimeSeriesSplit | sub 0..4(1.2초 간격, 5/5에서 멈춤): `tss == sub` 평가, `tss < sub`(−1 포함) 학습, 그 밖 아직 안 씀 |
- 3D `group` = 그 행의 출발일 번호(차트 1과 같다 — 그 출발일의 지형 점이 모인다).
- 표 카드: 블록 바로 뒤 `.chapter`(장면 `validation` 그대로 — 지형을 위에서 내려다봄), 제목 없이 `ValidationTable` + 코드 보기 링크.
  표에는 이미 `caption`이 있어 제목 h3를 따로 두지 않는다. 블록 사이 장면 틈이 생기지 않는다.

### 4.3 작은 단계(sub) — `ChartStage`

- `ChartStage`에 `subs?: number[]`(단계마다 작은 단계 수)와 `subMs?: number`를 더한다. 단계가 바뀌면 sub = 0에서 시작해
  `subMs`마다 +1, 마지막에서 멈춘다. 판이 화면 밖이면 타이머를 멈추고(IntersectionObserver, 이미 있는 불러오기 관찰과 따로),
  다시 들어오면 그 단계 처음부터.
- 움직임 줄이기(`prefers-reduced-motion`)면 곧바로 마지막 sub.
- 배치 함수는 `(stage, sub)`를 받고, `variant = 'stage:<n>:<sub>'` — 바뀔 때마다 3D 반대 슬롯(계획 5-3c `pickSlot`)으로 옮겨 간다.
  sub 간격(0.7초·1.2초)이 3D 슬롯 전환(`STAGE_DEBOUNCE_MS` 150ms + 전환 시간)보다 길어야 점이 튀지 않는다 — 눈 확인 때 전환이 끝나기
  전에 다음 sub가 오면 간격을 늘린다.
- 판에 `data-stage`와 함께 `data-sub`를 적는다(e2e·디버깅용).
